# Architecture

A static, dependency-free site: open `index.html` from disk or serve the folder (GitHub Pages). No build step, no CDN,
no framework. Everything renders client-side from one data file.

```
index.html                 page skeleton; loads data, base, then every section script; calls LB.boot()
data/leaderboard.js        window.LB_DATA = {...}   (generated by the benchmark's export_leaderboard.py)
data/leaderboard.json      the same data as JSON (linked as "Rankings as JSON")
data/pelican/*.svg         the models' pelican drawings (also generated); the page shows them only through <img src>
src/base.css               design tokens + shared components (cards, segmented controls, rank badges, bars, tooltip)
src/base.js                window.LB: element builders, formatting, vendor badges, filters, page chrome, boot()
src/sections/<name>.js     one file per section; registers itself with LB.register({...})
src/sections/<name>.css    styles for that section only; every class starts with the section's prefix
assets/fonts/              Geist (SIL Open Font License)
tools/shot.ps1             headless Chrome screenshot of the page or one section (?only=<id>)
```

## Section contract

```js
LB.register({
  id: "heatmap",          // DOM id of the <section>; also the #anchor
  order: 40,              // position on the page
  nav: "Heatmap",         // label in the header nav (omit to hide)
  render(el) {            // el = <section class="lb-section lb-wrap" id="heatmap">, already in the DOM
    el.append(LB.sectionHead({ title: "...", sub: "...", right: [/* controls */] }), LB.card("hm-card", ...));
  },
});
```

`index.html?only=<id>` renders just that section (used by `tools/shot.ps1 -Only <id>`).

Sections in page order, with their prefixes: frontier gap `fg-`, quality-vs-speed `sc-`, pelican `pel-`, overall `ov-`,
max-vs-max `mx-`, heatmap `hm-`, per-task `pt-`, agentic `ag-`, long context `lc-`, speed `sp-`, latency & memory `lat-`,
endurance `en-`, hardware `hw-`, models `mt-`, compare `cmp-`, in-progress `pg-`, methodology `me-`.

### Reading order

The `order` values follow one story (owner's call on 27 Nov, then researched and reviewed):

| order | sections | role |
|---|---|---|
| 10-14 | frontier gap, quality vs speed, pelican | highlights the owner put first, in this order |
| 20-25 | overall (ranking + verdict), max vs max | the answer on our own tasks, then best local vs best cloud |
| 40-58 | heatmap, per task, agentic, long context | where models win: overview first, then detail and the hard capabilities |
| 60-70 | speed, latency & memory, endurance, hardware | how they run on this PC |
| 80-98 | models table, compare, in progress, methodology | reference, tools and status; methodology last |

Rules that keep it readable when sections move:
- Every section opens with its own `LB.sectionHead` (none may rely on sitting right under the hero).
- A term is explained where the page first uses it (e.g. "text core" in quality vs speed, the first section with that
  score), not only in a later section or in the methodology.
- Text that points at another section says which one by name and link; "above"/"below" only within a section. In-page
  links end in ↓ or ↑ (the direction of the target), external links in ↗. The verdict's "Details ↓" links must go to
  sections placed after overall; a finding about a section above it uses `see` ("Frontier gap ↑").
- The hero's pick card links to the ranking ("Full ranking ↓") and the verdict ("Why this pick ↓"), since three sections
  now sit between them; the hero paragraph explains "text core", the first score on the page.
- The announcement bar's "New:" links to the newest section (now the frontier gap); the footer lists the first five nav
  sections under "Highlights & rankings" and the rest under "Explore", so keep the five most important first.

## LB API (src/base.js)

| Helper | Use |
|---|---|
| `LB.data` | the data object (`window.LB_DATA`) |
| `LB.h(tag, attrs, ...kids)` / `LB.s(tag, attrs, ...kids)` | HTML / SVG element builders. attrs: `class` (string or array), `style` (object), `onclick`..., `html`, `text`, any attribute |
| `LB.fmt.num(v,d) .int(v) .pct(v,d) .sec(v) .tps(v) .gb(v)` | formatting; scores are already 0-100; missing values print "—" |
| `LB.isNum(v)` | finite number check |
| `LB.quality(filter)` | models with a text-core score, best first; `filter` = placement filter value |
| `LB.byId(id)`, `LB.suite(key)`, `LB.score(m, key)` | lookups; `score` works for `textCore`, `allSuites`, core suite keys, `repo_replay`, `debug`, `long_horizon` |
| `LB.vendor(m)`, `LB.mono(m, size, {solid})` | vendor info; round vendor badge (stands in for a logo) |
| `LB.label(m)`, `LB.fullName(m)` | short chart label / "Name · variant" |
| `LB.PLACEMENTS`, `LB.matchPlacement(m, f)`, `LB.PLACEMENT_LABEL` | the "Compare all / Single GPU / Both GPUs / GPU + RAM / SSD" filter |
| `LB.seg(options, value, onChange)` | segmented control (black active pill) |
| `LB.tabs(options, value, onChange)` | tabs (lime active pill, `aria-selected` on the active tab) |
| `LB.select(options, value, onChange, label)` | dropdown; `label` sets the `<select>`'s `aria-label` (always pass one) |
| `LB.sectionHead({title, sub, right})`, `LB.card(cls, ...kids)` | section header, card |
| `LB.rank(i)`, `LB.bar(frac, color)`, `LB.chip(text, cls)` | "01" badge (lime when i = 0), progress bar, chip (`lime`, `dark`, `warn`) |
| `LB.rankRow(i, m, valueText, frac, sub, unit)` | ranked list row: badge, vendor badge, name, value, sub line, bar |
| `LB.tip.show(evt, html) .move(evt) .hide() .attach(el, html)` | dark tooltip; `LB.modelTip(m, extraHtml)` = standard model tooltip |
| `LB.onResize(fn)` | debounced window resize |
| `LB.openCompare(idA, idB)` | opens the comparison dialog (implemented by the compare section) |

## Data (data/leaderboard.json, schema `local-llm-leaderboard@1`)

- `generated`, `site`, `hardware {gpus[], cpu, ramGB, storage[], os, engine}`
- `core {perSuite, tasks, textTasks, suites[], textSuites[], gradedRuns, notes[]}`: `tasks` = core questions every model
  answers (all 9 core suites), `textTasks` = the subset behind the text core (vision excluded); `notes` = coverage notes
  from the common-task intersection (e.g. which models skipped vision), naming models by id
- `suites[] {key, name, short, group: daily|coding|agents, desc, inCore, tasks}`: 9 core suites + `repo_replay`, `debug`,
  `long_horizon` (agentic, reported separately). `tasks` = questions compared per model (sessions for `long_horizon`)
- `vendors {key: {name, org, color, letter, country}}`
- `models[]`:
  - identity: `id, name, short, variant, vendor, params, quant, placement (1gpu|2gpu|hybrid|stream|cpu|cloud), where`
  - flags: `recommended, reference, partial, speedOnly, status (done|running|queued|waiting), notes`. `reference` = a
    closed cloud model run through the GitHub Copilot CLI on the same tasks: shown for comparison, never ranked with
    the local setups. `LB.matchPlacement` only lets references through for the `"cloud"` filter, so `LB.quality("all")`
    and every placement filter leave them out; `LB.references()` returns them (best text core first). References have
    no speed, VRAM or endurance data.
  - memory: `vramGiB [gpu0, gpu1] | null, ramGiB`. A single-GPU setup has `null` for the GPU it doesn't use (the
    per-device reading there belongs to whatever the other benchmark lane had loaded)
  - `engineOf`: id of the model whose weights this entry runs on a different inference engine (engine A/B, e.g. the
    pick's Q4 weights on Basalt or Strata), else `null`. Such entries are an engine option, not a different model
  - `coreTasks, coreRows`: questions and graded rows behind the core score (rows = tasks x repeats), as "59 (177)"
  - `rows`: all graded rows of the model (every suite and repeat); `core.gradedRuns` is their sum
  - `scores {textCore, textCoreCI [lo, hi], allSuites, suites {core suite: 0-100}, repo_replay, debug, long_horizon}`.
    A model that skipped vision has `suites.vision = null` and `allSuites` covering its 8 text suites only
  - `suiteTimeS {core suite: median seconds}`; `agentFixS` = median seconds to the first correct fix in the core
    `agent_e2e` suite (solved runs only), the "fastest correct agent fix" metric
  - `fullSuites {score, tasks, rows, suites {core suite: {score, tasks, rows}}}`: each model's own full task set (more
    tasks / repeats where it had time), not directly comparable across models; `score` = mean of the unrounded suite
    accuracies
  - `effort, maxEffort`: reasoning effort of the run and whether it is the highest its family accepts; top-level
    `maxEffort {local[], cloud[], pending {local[], cloud[]}}` lists the max-effort runs and those still running
  - `agentic {repo_replay {rate, runs, tasks, meanScore, medianWallS, medianTimeToCorrectS, medianSteps, regressions,
    timeouts, minFreeCommitGiB}, debug {rate, runs, tasks, meanScore, medianWallS, medianTimeToFixS, reproducedFirst,
    rootCauseNamed, medianSteps}, long_horizon {rate, score, meanScore, sessions, runs, stagesPassed, stagesTotal, recall,
    violations, medianWallMin, maxPromptTokens, medianSteps, regressions, stuckEvents, lateEarlyDecode}}`. Every
    `meanScore` is on a 0-1 scale with 2 decimals; `long_horizon.score` is the same value on 0-100 (kept for
    compatibility; display and sort by `meanScore`)
  - `speed {decode, decodeSource, inTaskDecode, ttft, firstOutput, taskTime, prefill {8k, 32k, 64k, 117k}, ttftAt {...},
    decodeAt {...}, ctx, mtp {on, off, acceptance, draft} | null, concurrency [{streams, aggregate, perStream}]}`.
    `firstOutput` = median seconds until the first answer token or tool call of a core task (after any thinking);
    `ttft` and `firstOutput` have 2 decimals; `taskTime` = median wall time per core task; `decodeSource` = where
    `decode` comes from, in priority order: `"speed test, MTP on"`, `"speed test, short prompts"`, `"median during
    benchmark tasks"`. `mtp` is `null` unless on, off or acceptance was measured (a model can have only `acceptance`,
    e.g. speculative decoding through a separate draft model)
  - `cloudTaskTime`: references only, median wall time per core task through the Copilot CLI (not comparable with local speed)
  - `endurance {minutes, requests, sessionRequests, sideRequests, errors, ladderErrors, restarts, nCtx, thinking,
    decodeMedian, decodeP10, decodeP90, ttftMedian, cacheHit, acceptRate, sustainRatio, sustained {windowS, first, last,
    ratio, probeFirst, probeLast, probeRatio, depthAdjustedRatio}, byDepth [{bucket, n, decode, ttft, prefill}],
    ladder [{label, promptTokens, ttft, prefill, decode, clamped, skipped}], gpus [{index, name, tempMax, tempMean,
    powerMax, powerMean, smClockMedian, utilMean, throttledPct, powerCappedPct, thermalPct}], serverMem {startGiB, endGiB,
    maxGiB, growthGiB}, commitFreeMinGiB, serverCpuPct, restartsAt [min], timeline [{t, decode, prompt, side, error}],
    gpuSeries [{t, gpus [{i, temp, power}]}]}`: sustained-load test (cold context ladder + 20-min agent-style session).
    For a single-GPU setup `gpus` and `gpuSeries` only contain the GPU the model runs on
- `mtpSweep {model, points [{draft, tps}]}`, `nvme [{drive, seq, rand2m, rand256k, rand64k}]`
- `longContext {sizes [{key, label, tokens}], questions, answerBudget, depthBins [label], runs [...], queued [{id, model,
  setup {en, zh}}]}` or `null`: the long-context test (bench suite `long_ctx`). The same `questions` are asked at every size
  over one dump of real code per size (`tokens` = dump tokens with the Qwen3.8 tokenizer). Each run: `{id, model (a model
  id on the board), name, variant, vendor, engine, setup {en, zh}, running, closedBook {acc, ...} (the same questions with
  no files), bySize {<key>: {acc, ci [lo, hi], single, chain, list, n, solved, complete, lost, gained (vs 32K, paired),
  promptTokens, coldTtft, prefill, warmTtft, decode, taskTime, errors, truncated}}, skipped {<key>: reason}, depth {<key>:
  [single-hop % per depth bin, null when no question]}, largest}`. A size appears once all its questions are answered
  while the run is still going
- `pelican {prompt, system, perModel, credit {name, url}, entries [...], queued [...]}` or `null`: the "pelican riding a
  bicycle" test (Simon Willison's). Every model got the same `prompt` and `system` prompt and `perModel` tries to reply
  with one animated SVG, and every try is published. Each entry: `{id, model (a model id on the board when `onBoard`, else
  a stand-in id), onBoard, name, variant, vendor, local (false = cloud reference via GitHub Copilot), where, effort,
  complete (false while fewer than perModel tries exist), running, attempts [{n, file (site-relative path under
  `data/pelican/`, or null when the reply had no usable SVG), ok (a valid SVG that draws something), animated, problem
  (short reason or note), seconds (wall time; cloud: through the Copilot CLI), tokens (output tokens, thinking
  included), tps (local decode tok/s)}]}`. Entries come sorted: local first (best text core first), then cloud
  references; two entries can share a model name and differ by variant (e.g. effort). `queued [{id, model, name,
  variant, vendor, local, where, status: queued|running}]` = models whose job hasn't produced a try yet. A card opens
  on its first `ok` try and its pills switch between all of them. The drawings go on the page only through `<img src>`
  (never inline SVG, `<object>` or `<iframe>`), so a model's SVG can't run scripts or load anything, and only
  site-relative `.svg` paths are accepted
- `frontierGap {benchmarks [...], runs [...], queued [...], reference {...}}` or `null`: the frontier-gap test. The private
  suites are saturated, so the cloud references and the local setups also take two public hard benchmarks on the same
  harness: ARC-AGI-2 (`arc_agi2`: 40 of the 120 public evaluation tasks, exact grid match, pass@2) and AA-Omniscience
  (`omniscience`: 100 short-answer questions of the public set, graded by code, "I don't know" allowed). `benchmarks [{key,
  name, items, unit, about, url, source}]`: `items` = questions in a complete run, `unit` = what the score counts ("tasks
  solved"), `source` = credit and license. Each run: `{id, model (a model id on the board when `onBoard`, else a stand-in
  id), onBoard, name, variant, vendor, local (false = cloud via GitHub Copilot), where, running (true while the run is still
  going, cloud runs included), results {arc_agi2 {n, solved, score, ci [lo, hi], complete, effort, otherEffort, errors,
  truncated, medianSeconds, medianTokens, budget?, rerunBudget?}, omniscience {n, correct, incorrect, idk, score
  (accuracy), ci, index, complete, effort, otherEffort, errors, truncated, medianSeconds, medianTokens, budget?,
  rerunBudget?}}}`. `score` is 0-100 and `ci` its Wilson 95%
  interval (never zero-width once `n` > 0); `index` = 100 × (correct − incorrect) / n; `effort` = the effort most rows
  used, `otherEffort` = rows retried at another effort (e.g. after a CLI timeout); `budget` = the output-token budget
  (max_tokens) of a local run's rows, the smallest one if they differ, and `rerunBudget {tokens, n}` = the n tasks rerun
  with the larger budget `tokens` after they hit the first one (cloud rows record no budget); errors, timeouts and cut-off replies
  (`truncated`) count as wrong. A benchmark key is absent until the run has rows for it, and `complete` is false while `n`
  is below `items`. `queued [{id, model, benchmark, local, name, vendor, status: queued|running}]` = one entry per
  benchmark a run still has to do, cloud or local; `id` is the run's `id`, so a run can have results in one card and a
  placeholder in the other (an entry without `benchmark` goes in every card). `reference {<key>: {label, url, scores {model
  name: %}}}` = published numbers (the ARC Prize leaderboard, on its semi-private set), drawn as hollow ticks on the bar of
  the run with the same name. Each card lists complete runs first, then partial runs, each best score first; its "best
  cloud vs best local" gap uses complete runs only
- `hardwareFindings [{title, verdict: recommended|works|avoid, metric, body}]`
- `pairs [[idA, idB]]`, `verdict {pick, en, zh, headline, findings}`, `methodology [{title, body}]`. `verdict.en/zh` are
  generated from the data: top tier = local setups whose text core is at least the leader's `textCoreCI[0]` (the verdict
  panel uses the same rule); every cloud reference tied for the best score is named with its effort
- `verdict.headline {en, zh}`: the verdict panel's short lead (the pick, then the recommended upgrade); the panel falls back
  to `verdict.en/zh` without it. `verdict.findings [{key, tone: recommended|works|avoid|note, value, unit, title {en, zh},
  text {en, zh}, about? {en, zh}, link? {url, label {en, zh}}, model?, href?, see? {href, label {en, zh}}}]`: key findings,
  every number computed from the results; one is left out when its runs are missing. `unit` may be a plain string. The panel
  shows `engine` (the pick's weights on a faster engine) and `second-gpu` (a model for the free GPU) inside "Why this pick",
  and the first three others (`max-vs-max`, `long-context`, `effort`, then `giants`) as one "Other findings" row; `href` is
  the section with the details ("Details ↓"), `see` a second in-page link next to it, e.g. "Frontier gap ↑" to a section
  above the verdict, `model` a model id the panel offers to compare

Any value can be `null` (not measured yet); every section must render "—" or skip the model rather than fail.

## Updating the data

On the benchmark machine:

```
cd local-llm\bench
uv run export_leaderboard.py --out <this repo>\data
```

Only aggregates are exported. Task prompts, answers, task ids and anything that identifies the owner's accounts stay
private. The pelican test is the one exception: its prompt is public, and its drawings are published with anything that
isn't drawing (scripts, links, external references) stripped.
