# Architecture

A static, dependency-free site: open `index.html` from disk or serve the folder (GitHub Pages). No build step, no CDN,
no framework. Everything renders client-side from one data file.

```
index.html                 page skeleton; loads data, base, then every section script; calls LB.boot()
data/leaderboard.js        window.LB_DATA = {...}   (generated by the benchmark's export_leaderboard.py)
data/leaderboard.json      the same data as JSON (linked as "Rankings as JSON")
src/base.css               design tokens + shared components (cards, segmented controls, rank badges, bars, tooltip)
src/base.js                window.LB: element builders, formatting, vendor badges, filters, page chrome, boot()
src/sections/<name>.js     one file per section; registers itself with LB.register({...})
src/sections/<name>.css    styles for that section only; every class starts with the section's prefix
assets/fonts/              Geist (SIL Open Font License)
tools/shot.ps1             headless Chrome screenshot of the page or one section (?only=<id>)
```

## Section contract

```js
LB.register({
  id: "heatmap",          // DOM id of the <section>; also the #anchor
  order: 40,              // position on the page
  nav: "Heatmap",         // label in the header nav (omit to hide)
  render(el) {            // el = <section class="lb-section lb-wrap" id="heatmap">, already in the DOM
    el.append(LB.sectionHead({ title: "...", sub: "...", right: [/* controls */] }), LB.card("hm-card", ...));
  },
});
```

`index.html?only=<id>` renders just that section (used by `tools/shot.ps1 -Only <id>`).

Sections and their prefixes: overall `ov-`, quality-vs-speed `sc-`, heatmap `hm-`, per-task `pt-`, speed `sp-`,
hardware `hw-`, models `mt-`, compare `cmp-`, in-progress `pg-`, methodology `me-`.

## LB API (src/base.js)

| Helper | Use |
|---|---|
| `LB.data` | the data object (`window.LB_DATA`) |
| `LB.h(tag, attrs, ...kids)` / `LB.s(tag, attrs, ...kids)` | HTML / SVG element builders. attrs: `class` (string or array), `style` (object), `onclick`..., `html`, `text`, any attribute |
| `LB.fmt.num(v,d) .int(v) .pct(v,d) .sec(v) .tps(v) .gb(v)` | formatting; scores are already 0-100; missing values print "—" |
| `LB.isNum(v)` | finite number check |
| `LB.quality(filter)` | models with a text-core score, best first; `filter` = placement filter value |
| `LB.byId(id)`, `LB.suite(key)`, `LB.score(m, key)` | lookups; `score` works for `textCore`, `allSuites`, core suite keys, `repo_replay`, `debug`, `long_horizon` |
| `LB.vendor(m)`, `LB.mono(m, size, {solid})` | vendor info; round vendor badge (stands in for a logo) |
| `LB.label(m)`, `LB.fullName(m)` | short chart label / "Name · variant" |
| `LB.PLACEMENTS`, `LB.matchPlacement(m, f)`, `LB.PLACEMENT_LABEL` | the "Compare all / Single GPU / Both GPUs / GPU + RAM / SSD" filter |
| `LB.seg(options, value, onChange)` | segmented control (black active pill) |
| `LB.tabs(options, value, onChange)` | tabs (lime active pill) |
| `LB.select(options, value, onChange)` | dropdown |
| `LB.sectionHead({title, sub, right})`, `LB.card(cls, ...kids)` | section header, card |
| `LB.rank(i)`, `LB.bar(frac, color)`, `LB.chip(text, cls)` | "01" badge (lime when i = 0), progress bar, chip (`lime`, `dark`, `warn`) |
| `LB.rankRow(i, m, valueText, frac, sub, unit)` | ranked list row: badge, vendor badge, name, value, sub line, bar |
| `LB.tip.show(evt, html) .move(evt) .hide() .attach(el, html)` | dark tooltip; `LB.modelTip(m, extraHtml)` = standard model tooltip |
| `LB.onResize(fn)` | debounced window resize |
| `LB.openCompare(idA, idB)` | opens the comparison dialog (implemented by the compare section) |

## Data (data/leaderboard.json, schema `local-llm-leaderboard@1`)

- `generated`, `site`, `hardware {gpus[], cpu, ramGB, storage[], os, engine}`
- `core {perSuite, tasks, textTasks, suites[], textSuites[], gradedRuns}`: `tasks` = core questions every model answers
  (all 9 core suites), `textTasks` = the subset behind the text core (vision excluded)
- `suites[] {key, name, short, group: daily|coding|agents, desc, inCore, tasks}`: 9 core suites + `repo_replay`, `debug`,
  `long_horizon` (agentic, reported separately). `tasks` = questions compared per model (sessions for `long_horizon`)
- `vendors {key: {name, org, color, letter, country}}`
- `models[]`:
  - identity: `id, name, short, variant, vendor, params, quant, placement (1gpu|2gpu|hybrid|stream|cpu), where`
  - flags: `recommended, partial, speedOnly, status (done|running|queued|waiting), notes`
  - memory: `vramGiB [gpu0, gpu1] | null, ramGiB`
  - `scores {textCore, textCoreCI [lo, hi], allSuites, suites {core suite: 0-100}, repo_replay, debug, long_horizon}`
  - `suiteTimeS {core suite: median seconds}`
  - `agentic {repo_replay {rate, runs, tasks, medianWallS, medianTimeToCorrectS, medianSteps}, debug {rate, runs, tasks,
    medianWallS, medianTimeToFixS, reproducedFirst, rootCauseNamed}, long_horizon {rate, score, sessions, stagesPassed,
    stagesTotal, recall, violations, medianWallMin, maxPromptTokens}}`
  - `speed {decode, inTaskDecode, ttft, firstOutput, taskTime, prefill {8k, 32k, 64k, 117k}, ttftAt {...}, decodeAt {...},
    ctx, mtp {on, off, acceptance, draft}}`. `firstOutput` = median seconds until the first answer token or tool call of a
    core task (after any thinking); `taskTime` = median wall time per core task
  - `endurance {minutes, requests, errors, restarts, decodeMedian, ttftMedian, cacheHit, acceptRate, sustainRatio}`
- `mtpSweep {model, points [{draft, tps}]}`, `nvme [{drive, seq, rand2m, rand256k, rand64k}]`
- `hardwareFindings [{title, verdict: recommended|works|avoid, metric, body}]`
- `pairs [[idA, idB]]`, `verdict {pick, en, zh}`, `methodology [{title, body}]`

Any value can be `null` (not measured yet); every section must render "—" or skip the model rather than fail.

## Updating the data

On the benchmark machine:

```
cd local-llm\bench
uv run export_leaderboard.py --out <this repo>\data
```

Only aggregates are exported. Task prompts, answers, task ids and anything that identifies the owner's accounts stay
private.
